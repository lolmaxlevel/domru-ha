# Dom.ru Smart Intercom для Home Assistant

> ⚠️ **Внимание:** Интеграция находится в активной стадии разработки. Возможны и скорее всего будут ошибки.
>
> Тестирование интеграции проводилось на одной конкретной конфигурации с одним подключенным домофоном. Поведение интеграции при наличии нескольких домофонов, камер, адресов, лицевых счетов или других конфигураций Dom.ru пока неизвестно и может отличаться.

Интеграция для Home Assistant, позволяющая управлять умными домофонами и камерами Dom.ru через облачный API.

## Возможности

После установки интеграции вы получите доступ к следующим возможностям:

### 📹 Камеры

- Просмотр видеопотока с камер домофона в реальном времени
- WebRTC через встроенную интеграцию Home Assistant go2rtc

#### Звук камеры

Для камер, которые Dom.ru помечает как поддерживающие звук (`IsSound=1`),
интеграция перед получением временного URL обновляет пользовательскую медиасессию
через актуальный API. Поток Dom.ru использует контейнер HTTP-FLV с видео H.264 и
аудио MP3. Обычный HLS-плеер Home Assistant показывает видео, но может отбросить
такой аудиотрек. Интеграция автоматически регистрирует во встроенном go2rtc
локальный поток: видео H.264 передаётся без перекодирования, а аудио преобразуется
в AAC для HLS и Opus для WebRTC. К исходному HTTPS/FLV не применяются параметры
RTSP — это сохраняет совместимость с прямым fallback.

Для звука требуется встроенный go2rtc, который появился в Home Assistant 2024.11.
В Home Assistant OS и официальном Home Assistant Container версии 2024.11 или
новее он уже входит в поставку: интеграция запускает его автоматически, поэтому
устанавливать отдельный аддон, FFmpeg или собственный сервер и вручную настраивать
поток не нужно. Подробнее — в
[документации Home Assistant](https://www.home-assistant.io/integrations/go2rtc/).
Откройте стандартную карточку камеры и при необходимости снимите звук с mute —
браузеры обычно запрещают автоматическое воспроизведение аудио.

На Home Assistant версии ниже 2024.11, в нестандартной установке без managed
go2rtc, а также если go2rtc недоступен или настройка аудиопрокси завершилась
ошибкой, камера продолжит работать через прежний прямой HLS fallback, но
трансляция будет без звука.

Поддерживается только звук **от камеры к Home Assistant**. Передача голоса обратно
на домофон (двусторонний звук через SIP) в эту возможность не входит.

> **Известное ограничение:** превью/снимки камеры могут не отображаться, если
> API Dom.ru возвращает ошибку `500 Internal Server Error` на endpoint
> `/rest/v1/forpost/cameras/{cameraId}/snapshots`. Это проблема ответа
> upstream API для конкретного запроса снимка; для домофонных устройств
> интеграция использует `/rest/v1/places/{placeId}/accesscontrols/{deviceId}/videosnapshots`,
> если этот endpoint доступен. Видеопоток камеры при этом может продолжать работать.

### 🔐 Управление

- Кнопка открытия первой двери; если доступно несколько `access_controls`, интеграция добавляет отдельные кнопки для каждой точки доступа
- Сервис `domru.open_door` с параметрами `access_control_id` или `door_index` для открытия конкретной калитки, подъезда или двери
- Переключатель **Courier Auto Open**: открыть выбранную дверь при следующем входящем звонке и автоматически выключиться после одного срабатывания
- Селектор **Courier Auto Open Door** для выбора точки доступа, которую откроет courier auto-open; при одной доступной двери он отключен по умолчанию
- Если нажать **Open Door** без активного звонка, интеграция просто отправит команду открытия двери через API.
- Если нажать **Open Door** во время входящего звонка, интеграция ответит на звонок, откроет дверь и завершит звонок.

> **Важно:** Входящие вызовы зависят от SIP-регистрации. Dom.ru может отправить
> звонок в мобильное приложение вместо Home Assistant, поэтому отдельные вызовы
> могут быть пропущены интеграцией. Не используйте эту интеграцию как
> единственный критичный способ принять звонок или открыть дверь.

### 📊 Сенсоры

- **Баланс** - текущий баланс лицевого счёта
- **Сумма к оплате** - стоимость тарифа
- **Статус блокировки** - заблокирован ли доступ
- **Дата следующего платежа**
- Диагностические сущности показывают состояние SIP-подключения и сводку последних событий без вывода в основной список управления устройством

## Установка

### Установка через HACS (рекомендуется)

[![Открыть репозиторий в HACS](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=lolmaxlevel&repository=domru-ha&category=integration)

1. Установите [HACS](https://hacs.xyz/docs/setup/download) если ещё не установлен
2. Нажмите на кнопку выше или добавьте этот репозиторий вручную в HACS:
   - Откройте HACS в Home Assistant
   - Перейдите в раздел "Интеграции"
   - Нажмите на три точки в правом верхнем углу
   - Выберите "Пользовательские репозитории"
   - Вставьте URL: `https://github.com/lolmaxlevel/domru-ha`
   - Категория: `Integration`
   - Нажмите "Добавить"
3. Найдите "Dom.ru Smart Intercom" в списке интеграций HACS
4. Нажмите "Скачать"

### Ручная установка

1. Скачайте последний [релиз](https://github.com/lolmaxlevel/domru-ha/releases)
2. Распакуйте архив
3. Скопируйте папку `custom_components/domru` в папку `custom_components` вашего Home Assistant
4. Перезагрузите Home Assistant

## Настройка

После установки интеграции необходимо добавить её в Home Assistant:

[![Добавить интеграцию](https://my.home-assistant.io/badges/config_flow_start.svg)](https://my.home-assistant.io/redirect/config_flow_start/?domain=domru)

1. Перейдите в **Настройки** → **Устройства и службы** → **Добавить интеграцию**
2. Найдите **Dom.ru Smart Intercom**
3. Выберите способ входа:
   - **Телефон + SMS-код** - введите номер телефона, затем подтвердите код из SMS
   - **Логин + пароль** - используйте логин(номер лицевого счета) и пароль от личного кабинета Dom.ru
4. Нажмите "Отправить"
5. Интеграция автоматически обнаружит все доступные устройства и создаст соответствующие сущности

### Режим входящих SIP-звонков

Интеграция поддерживает два режима SIP. Откройте **Настройки** → **Устройства и
службы** → **Dom.ru Smart Intercom** → **Настроить**, затем выберите значение в
поле **Режим SIP-регистрации**. После изменения перезагрузите интеграцию.

| Режим | Как работает | Когда выбирать |
| --- | --- | --- |
| **По запросу (через FCM push)**, по умолчанию | Интеграция ожидает FCM-уведомление о звонке. В простое SIP-клиент не выполняет `REGISTER`. После FCM-события он кратко регистрируется для указанной в push двери, принимает `INVITE`, отвечает `100 Trying`, а после завершения вызова снимает регистрацию. | Рекомендуемый режим. Он создаёт меньше фонового SIP-трафика и повторяет логику мобильного приложения. Нужен работающий доступ Home Assistant к FCM/Google. |
| **Постоянная регистрация** | SIP-клиент остаётся зарегистрированным и обновляет регистрацию до истечения её срока. Вызов может прийти напрямую по SIP, без ожидания FCM-события. | Используйте как резервный вариант при нестабильной работе FCM или если важнее максимальная независимость от push-уведомлений. Этот режим создаёт больше постоянного SIP-трафика. |

В обоих режимах вызов может поступить на телефон или другое SIP-устройство
раньше Home Assistant. Не используйте интеграцию как единственный критичный
способ принять звонок или открыть дверь.

Если у аккаунта несколько точек доступа, в режиме **По запросу** одна
FCM-регистрация и один SIP-клиент обслуживают все обнаруженные двери. SIP-клиент
заранее получает учётные данные каждой двери и выбирает нужную учётную запись по
FCM-событию. В каждый момент обрабатывается только один активный вызов: повторное
событие того же вызова не создаёт новую регистрацию, а параллельный вызов не
может перезаписать уже активную SIP-сессию. Courier Auto Open срабатывает только
для двери, выбранной в **Courier Auto Open Door**. В постоянном режиме один
клиент может обслуживать несколько дверей только если API возвращает для них
одинаковые SIP-учётные данные.
